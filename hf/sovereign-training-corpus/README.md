# sovereign-training-corpus

Federated multi-source training corpus generated by the **AgentFishTank** swarm pipeline. 36 agents traverse GitHub repository trees, extract structured facts, and generate Q&A training examples across 7 training classes.

Authors: Ahmad Ali Parr, Jessica L. Williams (SNAPKITTYWEST) — Bel Esprit D'Accord Irrevocable Trust

---

## Overview

Each example is a `(question, answer, evidence)` triple anchored to a specific node in a repository's component tree. Evidence is a file path or component ID that grounds the answer.

**Sources:**
| Source | ID | Domain |
|--------|----|--------|
| NASA Common Metadata Repository | `CMR` | Earth science metadata, API |
| OpenMetadata | `OM` | Data governance, lineage |
| Autoware | `AW` | Autonomous driving stack |

**Training classes (7):**
| Class | Pipeline label | What it teaches |
|-------|---------------|----------------|
| `DISCOVERY` | Observe repo structure | What exists at this node? What is its role? |
| `EXTRACTION` | Extract metadata facts | What are the key facts about this component? |
| `CLASSIFICATION` | Classify component type | Is this a service, schema, test, API, config? |
| `RELATIONSHIP` | Map dependency edges | What does this component depend on / expose? |
| `ARCHITECTURE` | Reconstruct architecture | How do subsystems fit together? |
| `BEHAVIOR` | Trace execution path | What happens when this is called? |
| `RECONSTRUCTION` | Rebuild from spec | Given the spec, what would this look like? |

## Data Format

### JSONL (per example)

```json
{
  "question": "What is the primary role of the search-service component in the CMR system?",
  "answer": "The search-service handles Elasticsearch-backed catalog queries, translates UMM metadata into granule/collection search results, and exposes a REST API consumed by the CMR API gateway.",
  "evidence": "CMR/services/search-service",
  "training_class": "DISCOVERY",
  "corpus_source": "CMR",
  "node_path": "CMR/services/search-service",
  "confidence": "OBSERVED"
}
```

### TRAINING_CORPUS.json (per repo)

The AgentFishTank CorpusLoader fetches this from each fork at:
```
https://raw.githubusercontent.com/SNAPKITTYWEST/<repo>/main/TRAINING/TRAINING_CORPUS.json
```

Schema:
```json
{
  "repo": "Common-Metadata-Repository",
  "summary": {
    "domain": "...",
    "architecture_type": "...",
    "primary_language": "...",
    "major_components": [...],
    "data_stores": [...],
    "external_interfaces": [...],
    "evidence_files_read": [...]
  },
  "metadata_tree": {
    "node_id": "root",
    "node_type": "repository",
    "name": "...",
    "children": [...]
  },
  "relationship_graph": [
    {
      "from": "search-service",
      "to": "elasticsearch",
      "relationship": "QUERIES",
      "evidence": "CMR/services/search-service/src/cmr/search/data/elastic_search_index.clj",
      "confidence": "OBSERVED"
    }
  ],
  "training_corpus": {
    "DISCOVERY":      [{ "question": "...", "answer": "...", "evidence": "..." }],
    "EXTRACTION":     [...],
    "CLASSIFICATION": [...],
    "RELATIONSHIP":   [...],
    "ARCHITECTURE":   [...],
    "BEHAVIOR":       [...],
    "RECONSTRUCTION": [...]
  }
}
```

## Generation Pipeline

```
GitHub repo fork
      │
      │  AgentFishTank SwarmEngine (Swift/SceneKit)
      │  36 agents × 7 task types × all nodes
      │
      ├── TRAVERSE_TREE     → metadata_tree (node hierarchy)
      ├── EXTRACT_METADATA  → facts per component
      ├── BUILD_REL_GRAPH   → relationship_graph edges
      ├── RECONSTRUCT_ARCH  → architecture summary
      ├── GENERATE_TRAINING → Q&A examples per training class
      ├── VALIDATE_OUTPUT   → MATCH / PARTIAL / MISMATCH label
      └── SEND_TO_AGENT     → federated delivery + WORM seal
                │
                ▼
      TRAINING_CORPUS.json (committed to fork)
```

Agents run at 60fps, clustering around shared nodes. WORM seal on every completed training example — tamper-evident hash chain.

## Node Confidence Levels

| Level | Meaning |
|-------|---------|
| `OBSERVED` | Directly read from source file |
| `DERIVED` | Inferred from structure or naming |
| `INFERRED` | Pattern-based, not directly confirmed |
| `HYPOTHESIZED` | Architectural guess, needs validation |

## Usage

### Load with HuggingFace datasets

```python
from datasets import load_dataset

ds = load_dataset("SNAPKITTYWEST/sovereign-training-corpus", split="train")
print(ds[0])
# {
#   "question": "...",
#   "answer": "...",
#   "evidence": "CMR/services/ingest-app",
#   "training_class": "EXTRACTION",
#   "corpus_source": "CMR",
#   ...
# }
```

### Fine-tune on a training class

```python
from datasets import load_dataset

# Focus on ARCHITECTURE examples only
ds = load_dataset("SNAPKITTYWEST/sovereign-training-corpus", split="train")
arch = ds.filter(lambda x: x["training_class"] == "ARCHITECTURE")
```

### Use with sovereign-memory-twin

```python
from modeling_rmtn import CheckpointedMemoryHarness
import torch

harness = CheckpointedMemoryHarness(dimension=768)

# Ingest training examples as streaming events
for example in ds:
    vec = embed(example["question"] + " " + example["answer"])  # your embedder
    vec_tensor = torch.tensor(vec, dtype=torch.float32)
    state = harness.network(vec_tensor)
```

## Adding a New Corpus Source

1. Fork the target repo into `SNAPKITTYWEST/<repo-name>`
2. Add `CorpusSource` case and `repoMap` entry in `CorpusLoader.swift`
3. Run AgentFishTank — agents auto-assign to new corpus nodes
4. Generated `TRAINING_CORPUS.json` committed to fork under `TRAINING/`
